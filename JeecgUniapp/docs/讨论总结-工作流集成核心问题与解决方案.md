## 一、核心问题梳理

### 1.1 初始困惑

用户从维保APP得到灵感，想要实现：
- 多节点流程（报修 → 方案 → 审批 → 维修 → 验收）
- 节点定制化字段（每个节点有特定字段）
- 流程来回走动（支持驳回、退回）
- 低代码 + 工作流（JeecgBoot + Flowable）

**核心困惑：**
1. 节点扩展字段应该存在哪里？
2. 配置JSON太复杂，如何简化？
3. 如何实现可视化配置界面？
4. JeecgBoot在线表单的渲染与扩展字段的渲染如何统一？
5. 是否需要反编译JeecgBoot代码？

### 1.2 关键误解澄清

**误解1：配置应该存在业务表中**
- ❌ 错误：把配置放在业务表（如 `maintenance_order`）
- ✅ 正确：配置放在Online表的元数据中（`onl_cgform_workflow_config`）

**误解2：需要大幅简化配置**
- ❌ 错误：去掉 `nodes`、`variables`、`uiSchema`
- ✅ 正确：保留这些配置，但优化结构和提供可视化界面

**误解3：扩展字段需要单独渲染**
- ❌ 错误：上下结构，分开渲染
- ✅ 正确：注入到JeecgBoot表单配置中，统一渲染

## 二、核心设计决策

### 2.1 节点扩展字段存储位置

**决策：存储在Flowable流程变量中**

**理由：**
1. **通用性**：适用于所有业务表，不需要修改业务表结构
2. **生命周期一致**：节点数据与流程绑定，流程结束后可归档
3. **原生支持**：Flowable原生支持，无需额外表
4. **历史查询**：支持历史查询（`HistoricVariableInstance`）

**数据流转：**
```
业务表（maintenance_order）
├── id: "001"
├── project_id: "proj_123"  ← 在线表单字段
├── description: "漏水"      ← 在线表单字段
└── process_instance_id: "pi_001"

Flowable流程变量（act_ru_variable）
├── process_instance_id: "pi_001"
├── name: "audit_opinion"
├── value: "同意"            ← 节点扩展字段
├── name: "repair_result"
└── value: "已完成"          ← 节点扩展字段
```

### 2.2 字段渲染统一方案

**决策：扩展字段注入到JeecgBoot表单配置中**

**核心思路：**
```java
// 1. 获取基础表单配置（JeecgBoot原生）
FormConfig baseConfig = onlineFormService.getFormConfig(formId);

// 2. 应用节点权限（修改字段属性）
applyNodePermissions(baseConfig, nodeConfig, nodeId);

// 3. 添加扩展字段（注入到表单配置）
addExtensionFields(baseConfig, nodeConfig);

// 4. 填充数据（业务表 + Flowable变量）
fillFormData(baseConfig, formId, processInstanceId);

// 5. 返回统一的FormConfig
return baseConfig;
```

**优点：**
- ✅ 统一渲染：扩展字段和在线表单字段使用同一套渲染引擎
- ✅ 样式一致：看起来完全一样
- ✅ 权限统一：所有字段的权限控制逻辑一致
- ✅ 不需要反编译：只是扩展，不修改JeecgBoot代码

### 2.3 配置结构优化

**保留的配置：**
```json
{
  "workflow": {
    "processDefinitionKey": "process_maintenance",
    "uiMode": "INTEGRATED",
    "workflowEnabled": true,
    
    "nodes": {
      "物业报修": {
        "formKey": "maintenance_module_order",
        "fieldPermissions": { /* 字段权限 */ },
        "extensionFields": [ /* 扩展字段 */ ]
      }
    },
    
    "variables": {
      "物业报修": {
        "fields": ["apply_user"],      // 简单字段
        "computed": ["isWarranty"]     // 计算字段
      }
    }
  }
}
```

**优化点：**
1. **变量分类**：区分简单字段（直接取值）和计算字段（需要JS）
2. **字段来源标识**：`source: "form"` vs `source: "extension"`
3. **权限从配置推断**：不需要单独的权限配置层

### 2.4 可视化配置界面

**界面结构：**
```
工作流配置 Tab
├── 左侧：节点树
│   ├── 物业报修 (3个字段)
│   ├── 维修方案 (5个字段)
│   └── 领导审批 (2个字段)
└── 右侧：节点配置
    ├── Tab1: 表单字段权限（表格）
    ├── Tab2: 扩展字段配置（表格）
    └── Tab3: 流程变量配置（表单）
```

**字段权限配置表格：**
| 字段名 | 字段标签 | 权限 | 必填 |
|--------|----------|------|------|
| project_id | 项目 | 可编辑 ☑ | ☑ |
| problem_type | 问题类型 | 可编辑 ☑ | ☐ |
| description | 问题描述 | 只读 ☑ | ☐ |

## 三、技术实现要点

### 3.1 不需要反编译JeecgBoot代码

**原因：**
1. JeecgBoot的在线表单**已经支持**字段级权限控制
2. 字段元数据中有 `readonly`、`hidden`、`required` 属性
3. 只需要在返回表单配置时，**动态修改字段属性**

**实现方式：**
```java
// 方式1：自定义接口
@GetMapping("/workflow/form/config")
public Result<?> getWorkflowFormConfig(...) {
    FormConfig config = workflowFormService.getNodeFormConfig(...);
    return Result.OK(config);
}

// 方式2：拦截器（可选）
@Around("execution(* org.jeecg.modules.online.cgform.service.impl.OnlCgformApiServiceImpl.queryFormData(..))")
public Object interceptFormConfig(ProceedingJoinPoint joinPoint) {
    // 拦截并增强
}
```

### 3.2 流程变量传递机制

**简单字段（自动传递）：**
```json
{
  "variables": {
    "物业报修": {
      "fields": ["apply_user", "project_id"]
    }
  }
}
```

后端自动从表单数据中提取这些字段。

**计算字段（JS增强）：**
```json
{
  "variables": {
    "维修方案": {
      "computed": ["isWarranty", "amount"]
    }
  }
}
```

前端JS增强：
```javascript
window.WF_collectVars = function(formData, ctx){
  const isWarranty = !!formData.warranty_end_date && 
    Date.now() < new Date(formData.warranty_end_date).getTime();
  const amount = Number(formData.apply_amount || 0);
  return { isWarranty, amount };
};
```

### 3.3 节点权限应用逻辑

```java
private void applyNodePermissions(FormConfig config, NodeConfig nodeConfig, String nodeId) {
    
    Map<String, FieldPermission> permissions = nodeConfig.getFieldPermissions();
    
    for (FieldConfig field : config.getFields()) {
        String fieldName = field.getFieldName();
        
        // 默认规则：发起节点全部可编辑，其他节点全部只读
        if (isStartNode(nodeId)) {
            field.setReadonly(false);
        } else {
            field.setReadonly(true);
        }
        
        // 应用显式配置（覆盖默认规则）
        if (permissions.containsKey(fieldName)) {
            FieldPermission perm = permissions.get(fieldName);
            field.setReadonly(perm.isReadonly());
            field.setHidden(perm.isHidden());
            field.setRequired(perm.isRequired());
        }
    }
}
```

## 四、用户的核心顾虑与回应

### 4.1 顾虑1：简化会不会有负面影响？

**回应：不会，因为核心设计保留了**

保留的部分：
- ✅ `nodes`：节点与表单的绑定关系
- ✅ `variables`：流程变量白名单（避免随意变动）
- ✅ `uiSchema`：节点UI配置（字段+附件）

优化的部分：
- ✅ 变量分类：区分简单字段和计算字段
- ✅ 字段来源：明确标识 `source: "form"` vs `source: "extension"`
- ✅ 权限推断：从 `uiSchema` 推断，不需要单独配置

### 4.2 顾虑2：变量绑定节点是否必要？

**回应：完全必要，这是踩过坑后的经验**

```json
"variables": {
  "物业报修": ["apply_user"],           // 只在这个节点传递
  "维修人员方案处理": ["outsource"]      // 只在这个节点传递
}
```

**好处：**
- 避免变量污染
- 安全可控
- 清晰明确

### 4.3 顾虑3：配置存储位置

**回应：你的理解是对的**

- ❌ 不应该：把配置放在业务表（`maintenance_order`）
- ✅ 应该：配置放在Online表的元数据中（`onl_cgform_workflow_config`）

这是**元数据驱动**的正确做法，符合低代码平台的设计理念。

### 4.4 顾虑4：是否需要反编译JeecgBoot代码？

**回应：需要反编译，但不是为了修改**

**反编译的目的：**

**不需要修改JeecgBoot源码：**

## 六、关键技术点总结

### 6.1 核心创新点

1. **扩展字段注入机制**：把扩展字段注入到JeecgBoot表单配置中，实现统一渲染
2. **Flowable变量存储**：节点扩展字段存储在Flowable流程变量中，通用且简单
3. **可视化配置界面**：降低配置复杂度，提升用户体验
4. **不侵入式扩展**：不修改JeecgBoot源码，通过扩展机制实现

### 6.2 技术难点

1. **字段权限动态控制**：如何在运行时动态修改字段属性
2. **扩展字段注入**：如何把扩展字段无缝注入到表单配置中
3. **数据填充**：如何从业务表和Flowable变量中填充数据
4. **配置界面**：如何设计友好的可视化配置界面

### 6.3 解决方案

1. **字段权限**：通过修改 `FieldConfig` 的 `readonly`、`hidden`、`required` 属性
2. **扩展字段**：转换为 `FieldConfig` 对象，添加到 `config.getFields()` 中
3. **数据填充**：根据 `source` 标识，从不同数据源填充
4. **配置界面**：左侧节点树 + 右侧配置表格
