# 工作流 × 在线表单 集成使用指南（JeecgBoot）

本文档介绍 JeecgBoot 在线表单与 Flowable 工作流的集成方案与使用步骤，覆盖配置、运行期渲染、按钮模型、融合页、设计器增强，以及常用接口与权限说明。

## 1. 关键概念与存储

- UI 模式（ui_mode）：SPLIT（分离）/ INTEGRATED（融合）。按表单 + 流程定义 Key 进行配置。
- 节点 UI Schema：定义节点扩展区块、附件分组等（ui_schema_json）。
- 字段权限：节点维度对字段可编辑/只读/隐藏/必填的合成，来源优先级：节点显式配置 > 字段 fieldExtendJson(workflow) > 智能默认。
- 配置表：
  - onl_cgform_workflow_config（formId + processKey → ui_mode / ui_schema_json）
  - onl_cgform_workflow_node（formId/processKey + nodeId → 字段权限 / formKey / 自定义按钮等）

## 2. 配置入口（在线表单 → 工作流配置 Tab）

在表单设计页的“工作流配置”Tab 中集中完成：
- 流程定义 Key、UI 模式（SPLIT/INTEGRATED）
- 节点 UI Schema JSON 的编写、校验与保存
- 字段工作流权限：以字段为入口，批量编辑各节点权限，支持“起始节点可编辑”等模板动作
- 节点与表单Key 绑定（权威来源）：一键以当前表名填充
- 默认兜底配置（可选）：写入 head.extConfigJson.workflow（便于未显式配置时采用默认）

## 3. 运行期页面

### SPLIT 模式（通用表单页）
- 路由：`/workflow/form/:formType/:dataId?` → `UniversalFormPage`
- 能力：
  - 自动查询基本信息与流程状态（/workflow/onlineForm/form/basic-info、/workflow/render/process/info）
  - 智能按钮 `SmartButtonGroup`（/workflow/onlineForm/smartButtons），支持保存、提交、同意、驳回、认领、释放、转办等
  - 字段权限：调用 `/workflow/render/node` 合成权限后传入在线表单组件 `WorkflowOnlineForm`
  - 支持导出、版本历史、字段权限调试
  - 从“我的待办/任务列表”点击“办理”前会先调用 `/workflow/onlineForm/task/resolve`，再跳转 SPLIT 表单页

### INTEGRATED 模式（融合表单页）
- 路由：`/workflow/form/integrated` → `IntegratedForm.vue`
- 能力：
  - 节点扩展区块渲染（NodeBlock）与附件分组（ProcessAttachments）
  - 在线表单业务字段区（WorkflowOnlineForm），权限与 SPLIT 一致
  - 底部吸附操作条与智能按钮、处理意见
  - 流程历史/版本对比（formId 透传后端，字段名→标题映射更友好）
  - 提交时会同时写入任务完成与“表单快照”流程变量，便于历史与对比

## 4. 设计器增强（bpmn-js）

在 `views/workflow/designer/index.vue` 增强：
- 条件设置/清除；默认流；用户任务属性（assignee/candidate/formKey…）
- 任务监听器、执行监听器（新增与管理）
- 多实例/会签、服务/脚本任务、定时与事件定义
- 元素模板（审批、会签、服务任务等）
- 同步工具：
  - 同步到BPMN：`POST /workflow/definition/{id}/syncFromConfig` → 将配置表的 formKey 写回 BPMN（返回 XML，不直接部署）
  - 从BPMN读取：`POST /workflow/definition/{id}/syncToConfig` → 读取 userTask.formKey 回写节点配置（仅更新已存在记录）

说明：当前后端采用轻量正则处理 formKey，可按需升级为 moddle 结构化解析。

## 5. 常用后端接口（部分）

- 配置
  - GET `/workflow/config/uiMode`（cgformHeadId, processDefinitionKey）
  - GET/POST `/workflow/config/uiSchema`
- 在线表单 × 流程
  - GET `/workflow/onlineForm/form/basic-info`（tableName, dataId）
  - POST `/workflow/onlineForm/form/submit`、`/save-draft`、`/form/manual-start`
  - GET `/workflow/onlineForm/smartButtons`（tableName, dataId, taskId）
  - GET `/workflow/onlineForm/task/resolve`（taskId）
- 渲染/历史
  - GET `/workflow/render/node`（formId, processDefinitionKey, nodeId, processInstanceId?）
  - GET `/workflow/render/history`（processInstanceId, formId?）
  - GET `/workflow/render/history/detail`、`/history/compareLatest`（含 formId?）
- 任务
  - GET `/workflow/task/my`、`/workflow/task/list`
  - POST `/workflow/task/claim`、`/workflow/task/unclaim`
  - PUT `/workflow/task/{id}/complete`（支持传入 snapshot）
  - PUT `/workflow/task/{id}/delegate`、`/transfer`
  - POST `/workflow/task/{id}/comment`
- 附件
  - POST `/workflow/attachment`，GET `/workflow/attachment`，DELETE `/workflow/attachment/{id}`
- 设计器/定义
  - GET `/workflow/definition/{id}/xml`，POST `/workflow/definition/deploy`
  - POST `/workflow/definition/{id}/syncFromConfig`、`/syncToConfig`

## 6. 权限（Shiro）参考

- 任务：`workflow:task:my`、`workflow:task:list`、`workflow:task:view`、`workflow:task:claim`、`workflow:task:unclaim`、`workflow:task:complete`、`workflow:task:delegate`、`workflow:task:transfer`、`workflow:task:history`
- 附件：`workflow:attachment:add`、`workflow:attachment:list`、`workflow:attachment:delete`
- 配置：`workflow:config:ui:get`、`workflow:config:ui:save`（其余接口可按需加权限）
- 模型/定义：`workflow:model:*`、`workflow:definition:sync`

前端 `SmartButtonGroup` 亦会做权限兜底（基于 `permission` 字段和前端角色）。

## 7. 使用建议

1) 权责统一：formKey 以“在线表单工作流配置 Tab”为权威来源；设计器中的 formKey 作为参考/展示。
2) UI 模式：多流程场景建议在 `onl_cgform_workflow_config` 中为每个流程Key 单独配置；未命中时回落到 head.extConfigJson.workflow。
3) 字段权限：尽量用“节点显式配置”和字段 `fieldExtendJson(workflow)`，减少默认策略带来的不确定性。
4) 历史/对比：前端传 `formId`，后端映射字段名→标题，提升可读性；任务完成时传入 `snapshot`，形成闭环。
5) 设计器同步：同步到BPMN后建议手动检查关键节点的 formKey；需要部署才会生效。
